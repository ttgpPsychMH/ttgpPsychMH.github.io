# Periodic research-metric updates (proposal)

Keep `_data/research_metrics.yml` as the reviewed source of truth. Its verified 2 October 2026 snapshot, scopes and values are unchanged by this maintenance PR. No scraper or scheduled writer is introduced.

1. Review monthly. A future scheduled GitHub Actions reminder can open or update one review issue with source-profile links and a checklist, without fetching or writing numbers. A maintainer can instead use a calendar reminder; neither requires access to private CV data.
2. Obtain exact values from the author's authenticated source profiles, official exports, or authorized provider APIs. Google Scholar has no supported public metrics API: use a controlled manual review/export. For Scopus and Web of Science, first confirm API entitlements, licensing and that the returned field has the displayed scope. Keep API credentials in Actions secrets if an authorized adapter is introduced later.
3. Record source identity/profile ID, retrieval date, exact field/query, coverage/window and a permitted evidence reference in the proposed update. Retain only public-safe evidence; never commit credentials, session cookies, private account exports or unrelated personal data. A private evidence location may be referenced without publishing its contents.
4. Prepare a review PR with source-by-source before/after values and evidence. Keep Google Scholar all-time profile metrics, Scopus author positions for 2016–2025, and Web of Science Core Collection separate. A scope or time-window change needs explicit review. Use an authoritative aggregate for author-position percentages; do not infer them from incomplete publication lists or round chart heights into values.
5. Run existing site validation and inspect the homepage. Add validation for provenance or new fields if implementing an adapter. Require human review before merging any numeric changes, including decreases. Do not treat previous values as minimums or silently replace unavailable values with zero.

The current schema has one global `updated` date. Refresh that date only when every displayed source has been verified for the new snapshot. If any source is unavailable, retain the previous snapshot and leave the review open. A later change could introduce per-source observation dates and render them explicitly; avoid publishing mixed-age data under a new global date.

Leave `annual_series` empty unless a provider supplies exact values for explicitly identified years and the intended definition (annual citations versus cumulative totals, for example) is documented. Do not estimate yearly trends or combine database totals. Authorized API ingestion, if added later, should produce a draft PR with validation and provenance, never a direct push to `master`.
